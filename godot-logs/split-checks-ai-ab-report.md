## 1. 为什么本批用「数据驱动噪声底」而不是「逐行相同」

| 批次的 check 性质 | 可用判据 | 依据 |
|---|---|---|
| 批次① `layout`（纯函数族，模块 await=0） | **归一化后逐行相同** | 无物理、无协程，输出确定 |
| 批次② `steerbench`/`brakebench`（物理台架） | 跨组差 ≤ 组内极差 | 跨进程浮点漂移（`split-checks-bench-ab-report.md`） |
| **批次③ `ai`（本批，真物理 + 协程）** | **跨组差 ≤ 组内极差** | 见下 |

本批 5 项 check 全部走**真物理 + 真协程**，且 `opponents`/`aidiag` 按**墙钟**打印诊断块（`AGENTS §4.3` 双稳态同源）。实测同代码两跑即可差 3~8 行（见 §3），因此逐行判据不适用。

**采用的三条判据（数据驱动，不拍阈值）**：

1. **跨组差 ≤ 同代码组内极差** —— 迁移带来的差必须落在「同一份代码两跑也不一样」的量级内；
2. **存在至少一对 m↔c 完全零差** —— 迁移不是「普遍扰动」，而是能逐行复现 HEAD 的输出；
3. **判定串（`✔`/`✘` 收尾行）的集合不因代码版本改变** —— 逐跑漂移必须两组都出现。

> 三判据同源：本批的**噪声底 = 实测组内极差**；「≤ 噪声底」意味着无信号可归因于迁移。
> 该判据**不放松任何东西** —— 它比固定阈值（如 1%）更严，因为它要求逐项与**同代码自身的抖动**比较。

## 6. await 与协程层次（本批最需要盯的等价性维度）

`opponent_spawner` 的实证（`AGENTS §…`）：**多一层协程 = Godot 在 `physics_frame` 上恢复时机差 1 物理帧 → 日志发散 25856 行**。
本批对此的三重保证：

1. **await 数不增**：`ai.gd` 内 `await` **恰 8 处**（6 处 `_physics_frame.call()` + 2 处 `_sample_physics_ms.call()`），
   与迁移前该族函数体内的 await 数**一致**（structcheck 机器断言钉死 8/8）；
2. **`Callable` 注入不增协程层**：`await _physics_frame.call()` 与 `await get_tree().physics_frame` 的协程层次**完全相同**
   （`Callable` 只是调用方式，不引入 `await` 链）；协程链仍为 `_check_tick`(main) → `run_*`(ai.gd) → 采样器(main)，与迁移前同形；
3. **共享采样器不搬**：`_sample_physics_ms` 是 checks 族**共享**采样器，且被 main 的 `_after_world_ready`（测对手基线）使用 →
   **采样口径属 main，采样器留在 main、经 `Callable` 注入**（搬进模块会让 setup 路径反向持主，正是 `opponent_spawner` 实证过的陷阱）。

> 行为层的验证即 §3 结果：`obstacles` 0 差异、`opponents` 存在 `m2≡c3` 零差对 ——
> 若协程层次变了，`opponents` 不可能出现逐行零差（该族打印最密、对相位最敏感）。
