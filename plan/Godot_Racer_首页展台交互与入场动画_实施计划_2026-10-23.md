## 1. 目标、边界与设计决策

### 1.1 用户问题（截图和使用反馈）

- 赛车下方是大面积、薄且无侧壁的深色椭圆，看起来像地毯而非实体展台。
- 鼠标在底座上也会暂停车辆自转，交互热点错误。
- 希望首次进入首页时，展台从暗处升起、赛车同步出现，短暂暗场后灯光渐亮，形成“机械启动”的仪式感。
- 希望使用**项目原始 `icon.svg`**，不是随机生成新 Logo。

### 1.2 可验收成果

1. 有真实厚度、三级机械层次的多边形展台，轮胎与台面接触自然。
2. 展台/背景/Logo 均不会触发车模悬停；**只有射线实际命中赛车可见部件**才暂停自转。
3. 支持按住左键拖拽旋转赛车，松开后按规则恢复自动展示；不会误点首页功能。
4. 首次打开首页有短暗场、展台与车同步升起、灯带和聚光灯依次点亮、一次能量脉冲、进入稳定循环。
5. `icon.svg` 成为**展台朝向玩家的金属铭牌**；原图不被修改，不跟车旋转。
6. 开始游戏、选关、设置、帮助、退出、BGM、CLI 参数及现有输入路径不回退。
7. 工程加载、专项测试与三种分辨率下可使用；最终由用户真实试玩完成 U 验收。

### 1.3 视觉取舍（固定决策）

- 主题：**NEON GARAGE｜机械觉醒**；延续已有低多边形红色赛车、暗灰金属、冷蓝照明。
- 参考色：背景 `#0B0D11`；机身金属 `#343B46`；灯带 `#7FB3E8`；高光 `#68D9E8`。若本地主题已有一套稳定令牌，按现有主题协调，不硬覆盖全局配色。
- 赛车是画面主角。**展台整体不连续自转**；只有汽车旋转组件自转，独立扫描灯可以缓慢旋转。
- 第一版**不做**复杂地面变形/涟漪、大量悬浮粒子、体积烟雾、反复闪屏和高成本反射。
- 不大改左侧菜单排列。右侧视觉区、字幕与操作提示必须不重叠，维持玩家进入游戏的最短路径。

## 2. 建议技术架构（按本地真实节点映射，禁止平行造轮子）

以下是**逻辑架构示例**，不是要求强行新建同名节点；本地若已实现 `car_showcase`/`homepage`，优先改造并复用：

```text
Menu / HomePage (现有菜单；保持导航、设置、帮助、退出)
└─ ShowcaseHost (现有右侧展示 UI 容器；只该区域负责鼠标输入)
   └─ [现有 SubViewportContainer / TextureRect 等展示载体]
      └─ SubViewport (独立 3D 展示世界与摄像机)
         ├─ ShowcaseCamera3D
         ├─ ShowcaseLighting (环境光 + 低数量的局部光)
         └─ LiftRoot3D (整体升降；只移动一次)
            ├─ PodiumRoot3D (不持续旋转)
            │  ├─ BaseTier / MiddleTier / TopTier (有侧壁与厚度)
            │  ├─ EdgeLights (材质发光 + 轻量几何)
            │  ├─ PulseRing (仅入场显示一次)
            │  └─ BrandPlaque (正面原始 icon.svg 铭牌)
            └─ CarYawPivot3D (只绕局部 Y 轴旋转)
               ├─ VisualCar (仅展示网格，复用真实 GLB)
               └─ CarPickables (只属于赛车的可拾取碰撞体)
```

**模块职责**（先查本地归属后择优合并）：

- 展车控制模块：自动旋转、拖拽、输入状态机；不掌管菜单导航。
- 拾取模块：UI 坐标 → SubViewport 内相机坐标 → 3D Ray → 赛车拾取层命中；不管理展台渲染。
- 展台模块：多边形几何、静态层级、Logo 铭牌、装饰灯带。
- 动画模块：入场 Timeline、光照/材质参数与中断清理。
- 菜单适配层：创建/释放唯一展车实例，设置/帮助弹层的输入锁，生命周期。

新增脚本名称按本地结构决定，推荐独立、职责清晰；自有 `.gd` 必须遵守本地 `AGENTS.md` 的 **≤1000 行硬上限**，建议单模块 ≤500–600 行。发现旧超限文件应按照仓库规范先规划局部拆分，不能继续往旧超限文件堆新功能。不要擅自改已有 `AGENTS.md`。

**模型复用**：优先检查 `res://models/race_car.glb` 及当前本地展车模型源；避免首页加载带 `VehicleBody3D`、轮胎驱动、监控与引擎音的完整比赛物理场景。若当前已使用只读视觉实例，只在其已有变换树上添加旋转 Pivot 和拾取形状。

## 3. 阶段 P0：悬停误判与拖拽状态（第一优先）

### 3.1 输入真相与精准拾取

先定位当前“鼠标悬停即停止”的真实条件，判断是 UI 控件的 `mouse_entered`、大包围盒、射线层混淆、坐标换算问题还是输入转发问题；**先留原行为失败复现证据，再实施修复**。

约束：

1. 只有**射线命中赛车车身、轮胎、尾翼等被定义的可见部件**才判定为悬停。
2. 展台、Logo、外圈、背景和整个 ShowcaseHost 面板必须排除。不要用整块 `TextureRect`/`SubViewport`、整车巨大 `AABB` 或带大空白的盒形 Collider 冒充车模命中。
3. 在显示容器存在拉伸、居中、黑边/裁切、不同 DPI/视口缩放时，精确换算输入坐标；在展示区域外不得继续触发新拾取。
4. 使用 `Camera3D.project_ray_origin()` / `project_ray_normal()` 和展示世界的 `direct_space_state.intersect_ray()`，或经过同等验证的本地原有实现；设置只属于展示赛车的 **独立 collision mask/layer**。射线查询应放在物理空间安全的时点（通常 `_physics_process`）并读取已缓存鼠标坐标。
5. 命中物应归属 `CarPickables`；即使其他节点恰好使用相同 Collider 类型，也不能被当作汽车。
6. 拾取精度以**轮廓为准**：允许多块近似凸碰撞体、可维护的静态三角网格形状或等效方式，但要检查前后轮之间空隙、尾翼间隙、车身旁边背景；如果使用近似碰撞体，要明示误差并基于实际测试微调。
7. 禁止让本次拾取碰撞层进入比赛车辆物理碰撞规则；首页与比赛应隔离。

### 3.2 严格状态机

状态：`INTRO`（演出中） / `AUTO`（自动旋转） / `HOVER`（悬停冻结） / `DRAG`（按住左键旋转） / `BLOCKED`（弹层、窗口失焦或菜单离场）。实际实现可以是枚举加标志，但**不允许两处独立写自转使状态竞争**。

- 首次进入 `INTRO`；结束后检查当前鼠标是否真正指向汽车：命中则 `HOVER`，否则 `AUTO`。
- `AUTO`：局部 Y 轴每秒约 **10°**（策划初值），`delta` 驱动，不能绑定 FPS；落入有效车模射线进入 `HOVER`。
- `HOVER`：自转停止；离开车模且未拖拽，建议 **0.35 秒**后平滑恢复 `AUTO`（约 0.2 秒渐入速度，避免角度跳变）。悬停计时必须可取消，不重复生成无限 Tween。
- `DRAG`：只有鼠标按下时射线真正命中汽车才开始；水平鼠标移动驱动 `CarYawPivot`，旋转幅度采用“角度/实际像素”或归一化尺度，保证不同分辨率手感接近；支持多圈 360° 连续查看。**拖拽已开始后，指针移出赛车也持续拖拽直到松开**；鼠标移出窗口/失焦时安全终止，防止卡在 DRAG。
- 拖拽释放：指针仍命中汽车则 `HOVER`，否则进入 0.35 秒等待后恢复 `AUTO`；可有微弱惯性但第一版默认不加。
- `BLOCKED`：打开设置/帮助/退出确认、窗口失焦或菜单离场时禁止新增拖拽；如果正在拖拽，立即结束并释放捕获，回来后重新根据真实指针判定。
- `INTRO` 中若点击可见汽车：允许提前结束演出（≤0.2 秒平滑落定）并开始拖拽；若汽车尚未可见则不凭空响应。任何阶段左侧菜单按钮都**立即可点**。

**P0 必须通过后才能开展展台新造型**。初期至少用不同角度/像素点做命中表，尤其覆盖“鼠标在台面上仍自转”的原问题。

## 4. 阶段 P1：三层机械展台与实体接触

### 4.1 基础几何

- **下层 BaseTier**：16～24 边形截面，深灰金属，可见垂直侧壁、切角及厚度；比赛车轮距和轴距的投影外扩适量（建议预留车宽车长各约 10%～20% 视觉余量，最终由实际 GLB 尺寸决定）。
- **中层 MiddleTier**：略收窄/略抬高；金属槽与分段棱边；环形材质发光灯带；不要逐边放一盏真实动态灯。
- **上层 TopTier**：平整承托面，有明显厚度；四个轮胎视觉上正确落在台面，不能漂浮、穿透、超出台面边缘。
- 配置细小的正面镶嵌区域供品牌铭牌；靠摄像机的一侧可读，侧壁不被轮胎遮蔽。
- 可添加低强度顶部接触阴影/光斑，不能让赛车与展台像两个漂浮物。

不得把一个极扁的圆柱加大比例直接当作“完成”。当镜头从前侧看时必须清楚看到至少两层侧壁与灯带断面。

### 4.2 静态与动态分离

- 展台相对 `LiftRoot3D` 固定，不随 `CarYawPivot3D` 旋转。
- 仅扫描灯带的小装饰可缓慢移动；轮胎和车身一同旋转，不破坏整体模型轴心。
- 原有赛车的朝向和中心可能偏移，先测模型 AABB、轮胎落点及局部轴。中心错位先修展示 Pivot，不改 GLB 原始模型或比赛实体。
- 扩大机位、展台或修订旋转轴不得挤压左侧按钮、右下提示、不同屏幕安全边界。

**P1 验收**：近景可见层次；四轮接触合理；360° 旋转无切模型；展台点击/悬停不触发汽车冻结；左侧菜单所有功能保持原样。

## 5. 阶段 P2：首次开场 2.5 秒演出

### 5.1 Timeline（策划初值，实际效果可在记录中微调）

| 时间（秒） | 阶段 | 必须发生的视觉变化 |
|---|---|---|
| 0.00–0.25 | 暗场预热 | **只压暗右侧展车区域**，左侧标题/按钮正常可见；底边先出现一线柔和蓝光，严禁全屏突然闪黑 |
| 0.25–1.10 | 机械升起 | `LiftRoot3D` 从低位（参考展台自身厚度与画面裁切确定）平滑升到最终位置；车和台完全同步，整体不抖动 |
| 0.90–1.55 | 分层点亮 | 底层边框→中层灯带→顶部反射光依次增强；聚光灯逐渐照亮红色赛车，不能瞬间全部出现 |
| 1.55–2.10 | 唯一脉冲 | 外圈一圈能量光纹由内向外扩散，透明度衰减并销毁/隐藏；Logo 从暗到亮显现 |
| 2.10–2.50 | 落定与待机 | 光强回到低亮稳定值，开始自动旋转或保持真悬停；进入柔和灯带呼吸循环 |

**缓动建议**：升降 `EASE_OUT + TRANS_CUBIC/SINE`，灯光用平滑插值；避免反复 bounce。仅建议演出参数，不是现有实测事实。

### 5.2 生命周期契约

- 菜单入场前先完成必要资源创建与导入检查，避免“模型后加载才瞬闪一帧”；显示层在就绪前保持暗场占位，**菜单按钮不受影响**。
- 入场 Tween 只创建一套；离开菜单时 `kill()` 或相当方式清除旧 Tween/回调，移除展示视口实例，不残留点光源/音效/粒子。
- 首次进入完整演出；从比赛返回首页建议走 **≤0.4 秒快速恢复/淡入**（可用当前会话级标志，不新增 GameState 业务规则），减少重复等待。若本地已有明确的菜单重进规则，则按既有规则并记录差异。
- 设置/帮助/退出弹层覆盖时停止拾取与拖拽；演出可以继续，但必须保证弹层正确遮罩。退出/取消后重新判断输入。
- `--check`、`--level` 必须保留直连；`--autostart` 不受动画阻塞；`--shot-menu[=N]` 原功能不删除，注意旧第 30 帧截图可能截到入场中间态。最终静态截图应使用足够大的帧号（例如 180 帧）或已有正式截图入口。
- 禁止 `await` 入场动画才允许玩家按开始；禁止改比赛时钟、物理时序或加载完成条件。

### 5.3 待机灯效

- 待机用约 2.5～4 秒低振幅呼吸周期，边缘发光只在低亮与中亮间平稳变化。
- 扫描线最多一条主扫描 + 必要的弱辅光；显著粒子 ≤少量且可关闭，先测性能再决定是否启用。
- 不使用高频闪烁、强烈屏幕曝光变化、连续铺满背景的明亮网格。

**P2 验收**：全流程无明显闪现/穿模/假黑屏；1 次脉冲；重复进入不重复播放音效、不积累节点；按钮第一帧可用，点击开始不会被演出阻断。

## 6. 阶段 P3：使用原始 icon.svg 制作品牌铭牌

### 6.1 资源与位置

- 优先核对本地 `res://icon.svg` 是否与用户本次提供的 SVG 一致；原始图标是 **128×128 深蓝灰圆角背景、红色赛车剪影、浅蓝座舱**。若本地资源不同，先记录差异，使用用户提供的 SVG 的**独立派生文件**，不得默默覆盖本地图标。
- 推荐置于**朝镜头的前侧金属壁板**，作为微凹陷金属铭牌；1:1 比例，四周留边；Logo 在首屏正常尺度可辨认。
- 优先采用 SVG 的 Godot 导入纹理；若渲染不清晰，可生成透明/完整背景 PNG 派生图并记录生成方法、色彩和尺寸。使用 `StandardMaterial3D` 等支持的 3D 材质来显示。**不得用 `CanvasTexture` 直接套 3D 网格**。
- 铭牌可用弱蓝框照亮，但原 icon 的红色主体保持红色，禁止单色重绘。
- 可在旁边辅以小号 `GODOT RACER` 铭文；若 720p 下不可读，宁可移除文字，不牺牲 Logo。

### 6.2 动画与拾取

- 1.55～2.10 秒随光脉冲渐亮，结束后固定低亮；铭牌不自动旋转。
- `BrandPlaque` 全树不加入赛车拾取集合。
- 镜头角度导致遮挡时首先调整铭牌在侧壁上的安装角度/位置，不能把 Logo 贴在车身或漂浮到车顶。

## 7. 性能预算、降级、可访问性

- 以**本地修改前/修改后的同机器、同分辨率、同场景、相同设置**为基准，记录稳定阶段 FPS 或 CPU/GPU 帧时统计；建议新增视觉表现造成的稳定帧时开销不超过 **10%**，超过时先削减动态灯/阴影/粒子/视口分辨率，再考虑其他方案。这个 10% 是设计预算，**不是项目历史测量值或可以更改既有测试阈值的理由**。
- 固定光照优先环境光、1 个关键灯及少量补光；灯带以 Emission 材质模拟，不为每段增加真实实时光源。
- 如果 Glow/透明效果在本地渲染器或显卡不可用，必须提供无 Glow 的 Emission/颜色高亮方案；不以改全局渲染器作为默认修复。
- 避免高频透明层叠、过多粒子、每帧动态重建 Mesh 或反复加载 SVG/GLB。
- 短暗场只影响展车区域；不要全屏闪烁。主菜单全程可阅读、可聚焦、可操作。保证弹层优先级和 ESC 行为。
- 如已有“减少动态效果/画质模式”设置，则尊重它；如没有，不必为这一工单大改设置页，只将简化模式的开关留在展台局部配置，并在报告中注明。

## 8. 测试矩阵与通过条件

### 8.1 自动化：先红后绿（每阶段均保存真实运行记录）

| 编号 | 测试动作 | 必须通过 |
|---|---|---|

| INTRO-02 | 升降中点击“开始游戏” | 正常进入赛道，旧动画清理、不残留回调 |
| INTRO-03 | 连续“首页→比赛→首页”三次 | 每轮仅一个展台/视口实例，无资源或灯效积累 |
| ART-01 | 比对真实轮胎落点与上层台面 | 无穿模、漂浮、出界，侧壁至少两层可辨 |
| LOGO-01 | 检查原 icon 内容、朝向、比例、灯光、拾取 | 源 SVG 未覆盖，清晰显示，鼠标落 Logo 不停赛车 |
| UI-01 | 选关、开始、设置、帮助、退出、ESC、Tab、BGM | 与本地修改前行为等价，无菜单功能回退 |
| CLI-01 | `--check`、`--level`、`--autostart`、`--shot-menu` | 原分流有效；视觉演出不阻塞或破坏入口 |
| SIZE-01 | 1280×720、1366×705、1920×1080 | 展台、车、Logo、菜单提示完整，按钮不互压 |
| PERF-01 | 相同设置、同机器的改前改后稳定段 | 记录相对帧时变化；预算不满足则先降成本 |

**注意**：只读源码测试不能代替实际 Godot 渲染与真人鼠标体验；自动脚本测试用输入模拟验证状态，再以实体窗口逐点确认拾取和帧时。避免凭开发者打印信息伪造实际命中测试。

### 8.2 建议执行顺序

1. 静态脚本解析/资源导入完整性；先确认 Godot 版本后使用其真实可用命令。可参考：`godot --headless --path .\godot-racer --editor --quit`，但运行路径和可执行文件须由本地实际确定。
2. 原有菜单和交互专项；添加 P0 的最小失败测试后跑红，再修到绿。
3. 各阶段的专项场景测试、截图对比、逐项真实鼠标操作。
4. 必要的 UI/输入/音频生命周期回归；**物理/AI 的重型回归不应因为纯首页改动就随意并行运行**，如果项目规范要求则串行执行并保留结果。
5. 对本机真实运行的 1280×720、1366×705、1920×1080 截图、初次演出视频和拖拽视频保留证据；如果某种模式只是离屏渲染，必须注明不是实体显示测试。
6. 检查每个改动 `.gd` 文件行数、两份 AGENTS 是否保持未改、所有 UID 与导入路径、`git diff --check`；**不允许为过测试而放宽现有断言/阈值**。

### 8.3 玩家真人 U 验收（执行 AI 不能替用户签字）

请用户在真实窗口检查：第一次进首页是否自然、是否“黑一下亮起”但不闪屏；车模是否比底座更醒目；悬停车/台、拖拽流畅度、鼠标离开后恢复；图标是否辨认清楚；返回首页体验是否多余；5 分钟后是否仍觉得灯效过亮。未获用户确认只可写 `U: 待验`。
