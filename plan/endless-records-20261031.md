# 无限畅玩与本地最佳纪录：设计与实施计划

## 用户已确认的规则

- PC 优先，五关任选。选关时可切换“普通竞速 / 无限畅玩”。
- 普通模式：每关只保留完整两圈比赛的最佳总时间，不另保存普通单圈纪录。
- 无限畅玩：没有完赛圈数上限；沿用现有 AI 开关，AI 开启时也持续驾驶；单圈最佳纪录单独持久化，不混入普通模式。
- 无限模式 HUD 显示本圈、上圈、本次最快和已完成圈数，不显示整场总时间或普通比赛名次；可通过现有暂停菜单重开或返回。
- 暂停不计时，沿用现有统一比赛时钟和真实计圈入口，不另写计时器。

## 已按用户澄清实施的交互方案

- 在现有选关页增加模式切换按钮和“最佳纪录”按钮，不重做首页。
- 最佳纪录弹层显示五关各自“普通模式两圈最佳总时间 / 无限畅玩最佳单圈”，未取得成绩时显示“暂无纪录”。
- 正常完成两圈后更新普通纪录；无限模式每完成一圈便尝试更新单圈纪录。仅更快的成绩覆盖旧值。
- 默认按“同一关”保存，不按随机组合和极速档位拆分排行榜；记录页注明当前为本地个人纪录、可能使用不同赛事条件。这不是联网竞技排名。
- 当前沿用已经批准的圈速口径：GO 起表，首圈包含起跑段；首次经过起跑线只标记发车，不误计为完成一圈。
- 正常退出后再次启动仍能读取纪录；中途退出不生成普通两圈纪录，已保存的无限模式单圈不丢失。

## 实现边界与文件归属

- `game_state.gd`：保存当前模式，统一给出本局目标圈数；持有轻量纪录存储对象，保持一份纪录真值。
- 新增 `scripts/race_records.gd`：只处理本地版本化纪录、数值校验、读写错误和安全落盘。使用 `user://`，不联网、不加数据库依赖。
- `main.gd`：将真实玩家单圈/完赛事件交给纪录存储；无限模式不触发普通结算。
- `opponent_spawner.gd` / `ai_opponent.gd`：无限模式允许 0 作为不限圈目标，AI 不因到达普通两圈目标而发出完赛。
- `menu.gd` / `menu_overlay.gd`：模式选择和纪录查看；复用现有弹层、主题、焦点与缩放。
- `hud.gd` / `pause_menu.gd`：显示正确的无限模式信息；不复制比赛状态或圈速公式。
- 数据仅存两类个人最好成绩及必要版本字段；首版不做历史逐圈数据库、删除纪录、云同步、回放或反作弊系统。
