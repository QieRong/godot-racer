## 三、数据结构与配置（改动清单）

### 3.1 DSL 新增高度剖面（沿用现有"文本 + 严格校验"风格）

```
elevation_profile := ""                       # 空 = 无起伏（阶段 3 之前是默认值）
elevation_profile := "0:0, 0.22:4.5, 0.45:0.8, 0.70:5.0, 1.0:0"   # t:高度(米)
```

**规则（凡违反一律报错并指出第几项，不许静默修正）**：

| 规则 | 理由 |
|---|---|
| `t` 必须严格递增且 ∈ [0,1]，最后一项必须 `t=1.0` | 否则采样顺序错了，剖面会折返 |
| 首项高度 = 末项高度（都写 0） | 闭环：`Y(0) = Y(L)` |
| 所有高度 ≥ 0（本阶段不允许下凹到负值以下超过 −3 m） | `plate_top` 是按 `min_road_y` 算的，太深会让兜底平板离路面太远 |
| 控制点之间的**设计坡度 ≤ 上限的 85%**（L1–L3/L5 ≤9%→设计 ≤7.6%；L4 ≤12%→设计 ≤10.2%） | 三次插值在控制点附近会**过冲**，留余量后实测峰值才压得住上限 |

### 3.2 `LevelConfig` 新增字段（`scripts/level_config.gd`）

```gdscript
@export var elevation_profile := ""     ## 高度剖面 DSL（空 = 平地）
@export var grade_limit := 0.09         ## 本关坡度硬上限（L4 设 0.12）
```

`apply_to_track()` 里 `track.set("elevation_profile", …)` / `set("grade_limit", …)`。
**五关 `.tres` 在本阶段全部保持 `elevation_profile = ""`**（除了临时给 L1 开坡做管道联调）。

### 3.3 `track_layout.gd` 新增两个静态函数（几何逻辑的唯一样源）

```gdscript
## 把 "t:高度" 文本解析成 {ok, points:[{t,h}], error}
static func parse_elevation(text: String) -> Dictionary

## 按弧长给点列叠加高度。返回 {ok, points, error, max_grade, grade_arc}
##   total：曲线当前长度（用 XZ 长度先算）；sample：按 t×total 取高度
static func apply_elevation(pts: PackedVector3Array, profile: String,
        grade_limit: float, step: float) -> Dictionary
```

**关键实现点（都来自阶段 1 踩到的真实坑）**：

- 高度剖面用**独立 Curve3D**，并且**必须按 Catmull-Rom 给手柄**
  （`tangent = (next - prev) / 6`）—— Godot 的 `Curve3D` **没有 `cubic_interp` 属性**，
  且不给手柄时它就是折线（阶段 1 已写进 `engineering-notes` 46/47）。
- **环状鬼点保证接缝 C¹**：把剖面点首尾各补一个环绕邻点
  （`(t_{n-1}-1, h_{n-1})` 与 `(1+t_1, h_1)`）后再建曲线，这样 `Y'(0)` 与 `Y'(L)`
  由**同一对邻居**算出 → 数学上相等 → 每圈过起跑线时不会被"顶"一下。
- **顺序**：先建 XZ 骨架 → 量 XZ 长度 → 叠高度 → 重建曲线 → **此时 `_road_length` 才是三维弧长**。
- **实测坡度必须在最终曲线上量**（按固定弧长采样做有限差分），不能在控制点折线上量
  —— 阶段 1 的教训：在折线上量会把折角当成曲率（假警报）。
- 坡度超限时**报错并在报错里给出超限处的弧长**（哪一段坡太陡）。

## 四、逐项实现规格

### 4.1 地形带（对应总体计划 §5.3）

**决定：用 `ArrayMesh`（`SurfaceTool` 手写条带），不用 `GridMesh`。**

| 方案 | 代价 | 接缝 |
|---|---|---|
| `GridMesh` 规则网格 | ±120 m × 1.4 km、2 m 站距 → **约 17 万三角面**，且网格方向与赛道无关 | 必然错开，要额外补 |
| **ArrayMesh 沿赛道横断面** | 2 m 站距 × 每站 10 顶点 → **约 7200 三角面** | 与路面**共用同一个顶点**，数学上无缝 |

**横断面（每站一次，`H = road_width/2`，`y_i` = 该站路面高度）**

| 横向偏移 w | 高度 | 说明 |
|---|---|---|
| `±H`（路面外沿） | `y_i` | **与路面网格完全同一个顶点** → 无缝 |
| `±(H+2.0)` | `y_i − 0.10` | **路肩**：微降排水。护栏在 `H+1.2`，**站在路肩上**（1.2 < 2.0，护栏底下不是悬崖） |
| `±(H+8.0)` | `y_i − 0.80` | 路缘带 |
| `±(H+30.0)` | `lerp(y_i − 2.5, plate_top, 0.45)` | 缓坡带 |
| `±(H+120.0)` | `plate_top` | 与兜底平板**齐平** → 边缘不悬空、不穿模 |

**不变量（`--check=elevation` 逐点断言）**

1. `terrain_y(w) ≤ y_i − 0.05`（地形永不高过路沿 → 不盖路面、不穿模）
2. `terrain_y(w) ≥ plate_top`（永不掉到平板以下）
3. 外沿 `= plate_top`（不悬空）

**碰撞：地形带不加碰撞。** 护栏在 `H+1.2` 处有 12 m 高空气墙，车物理上到不了地形带；
所以它纯视觉 → 零物理开销、零 trimesh 性能风险（`track_generator.gd` 第 238 行记着
高面数 trimesh 会让 `VehicleBody3D` 掉帧）。兜底平板继续留在 layer 1 当安全网。

**兜底平板**：顶面从固定 `y=0` 改成 `plate_top = min_road_y − 1.5`（曲线建好后才算得出），
否则 L3 的下凹弯会把路面埋进平板里。

**共用坐标**：把护栏里那段"自适应真实弧长走环"抽成 `_walk_ring(want_step)`，
护栏与地形带**同源**，环首尾重合检查继续生效。

### 4.4 AI：上坡收油 / 下坡早刹 / **物理极限限速**

**（a）坡度感知**（对应你批注的第 3 条）

- 前视 8 m 取高度差算 `grade = (y(arc+8) − y(arc)) / 8`
- `grade > 3%`（上坡）：`limit *= clampf(1 − 4.0·(grade − 0.03), 0.55, 1.0)`
  （12% 坡 → 收到 64%）。物理依据：12% 坡的沿坡重力分量 = 1.18 m/s²，持续上坡动力裕度被吃掉
- `grade < −3%`（下坡）：把弯道采样距离 12/28/48/72 m 乘 `(1 + 0.6·clampf(−grade/0.12, 0, 1))`
  （更早预判），并把"超速才刹车"的死区从 3.0 m/s 收到 1.5 m/s

**（b）⚠ 物理极限限速（阶段 1 评审发现，不修 L5 必炸）**

现状：AI 弯道限速靠"折角 → 百分比"，下限 `min_speed_frac = 0.30`。
L5 极地：极速 240×0.9 = 216 km/h → **最低只能降到 65 km/h**；
但冰面 `a_lat = max_lateral_accel(16.0) × friction_multiplier(0.5) = 8.0 m/s²`、发夹 `R=18 m`：

```
v_max = sqrt(a_lat · R) = sqrt(8.0 × 18) = 12.0 m/s = 43.2 km/h   （×0.85 安全系数 → 36.7）
65 > 43.2  →  AI 在冰面发夹弯必然推头出界
```

**修法**：`setup()` 注入抓地力时同时把 `max_lateral_accel` 按倍率缩放（保存基准值，避免反复
setup 越乘越小）；`_target_speed()` 里加一条**不受百分比下限约束**的物理限速
`limit = min(limit, speed_limit_kmh(R_i, a_lat))`。
即：`min_speed_frac` 是"对极速的下限"，物理极限是"对地面的上限"，**两者取小，物理极限不允许被抬回去**。

各关对照（用现役 `max_lateral_accel = 16.0`）：

| 关 | μ 倍率 | a_lat | 最紧弯 R | 物理限速(×0.85) | 现下限(30%) | 够不够 |
|---|---|---|---|---|---|---|
| L3 雨夜 | 0.7 | 11.2 | 20 | 46 km/h | 54 km/h | 勉强 |
| L4 荒漠 | 0.85 | 13.6 | 60 | 88 km/h | 59 km/h | ✔ |
| **L5 极地** | 0.5 | 8.0 | 18 | **37 km/h** | 65 km/h | ❌ 必须修 |

### 4.5 ⚠ 顺手修掉：L4 荒漠 AI 卡死（试玩期间新发现，**既有缺陷**）

**实测证据**（`--check=opponents -Level 3`，关卡 4 荒漠 6 静态 + 2 动态）：
AI 连续自救 **9 次**后被超时掐断，卡死位置固定 `(-271.27, 1.447, 116.81)`、
离中心线 **0.02 m**、姿态 up.y=0.99（没翻）、**接地 2/4**、速度 **0**、y=1.45 m（骑在石头上）。

**机理**（日志 + 几何一致）：

1. 关卡 4 的**动态滑动路障**扫掠范围约 1.2~4.4 m，**会扫过 AI 的 2.4 m 巡航车道**；
2. AI 按 `clear_lane_for()` 往**中线**闪避；
3. 而静态石头按 `_pick_lateral()` 就摆在**离中线 ≤0.125 m** 的带子里 → AI 撞上/骑上去；
4. 自救又把它推到石头上 → 永久卡死。

**修法（三步，缺一不可）**

| 步 | 做法 |
|---|---|
| ① | `clear_lane_for()` 的**触发**只认动态路障（静态障碍按设计不占 AI 车道） |
| ② | 但**选替代车道**时必须把**所有**障碍（含静态）都算作占用，并在更长前瞻（horizon×1.5）上检查；候选车道 = 每个障碍的两侧绕行 + 路两侧极限，取"离当前车道最近且未被占用"的那个 |
| ③ | 没有任何空车道时 → 返回当前车道并置 `_blocked_ahead`，让 `_target_speed()` 把目标速度压到"能在障碍前停住"（`sqrt(2·a_brake·d)`）→ **排队而不是硬挤** |

> 注：我试过只做 ①，**实测没修好**（仍卡在同一位置），已回退。所以这次三步一起做，
> 并以"L4 上 `opponents` 零自救跑完一圈"作为唯一验收。

**验收覆盖**：`run-all-checks.ps1` 里 `opponents` 增加**一行关卡 4**（现有那行是关卡 5）——
两行同名不同关卡（表格里"关卡"列能区分）。菜单里的检查项列表会去重显示。

### 4.6 ⚠ 顺手修掉：验收自动驾驶在冰面上开不完一圈

`main.gd` 里 `--check=lap` / `elevation` 用的自动驾驶是另一套瞄准逻辑，它**没有物理极限限速**。
L5 的冰面发夹弯（37 km/h 极限）它压不住 → 会推出界/靠兜底复位，检查就会忽红忽绿。
修法：这套自动驾驶改成 `racing_line.gd` 的限速（与 AI 同一份），**不新增代码路径**。

### 5.2 四轮接地射线的规范（对应你批注的第 4 条）

每个物理帧、四个轮子各一条：

```gdscript
var q := PhysicsRayQueryParameters3D.create(
        w.global_position,                                   # 轮心（世界坐标）
        w.global_position + Vector3.DOWN * (w.wheel_radius + 0.60),
        1,                                                   # mask=1：只打路面/地形
        [car.get_rid()])                                     # 排除自己
var hit := space.intersect_ray(q)
```

- 打空 = 该轮**悬空**；记录 `(弧长, 轮名, 车身 y, 路面 y, 速度)`
- **判据：连续打空 > 0.15 s（120 Hz 下 18 帧）即判失败并退出本项检查**
  —— 允许过坡顶那一瞬的正常离地，不允许"某个轮子长期不接地"（那说明地形/路面对不齐或有台阶）
- 顺带统计全程接地率，要求 **≥99%**
- 失败时打印**最严重的 5 处**及附近的高度剖面，直接定位是哪个坡做坏了

### 5.3 `--check=assets`（对应你批注的第 7 条）

现状靠推断：`ground_texture` 留空 → `ground_L<索引>_<天气slug>.png`。
风险是"改了天气或调了关卡顺序就静默配上另一关的贴图"。

| 断言 | 说明 |
|---|---|
| 贴图文件存在**且已导入**（`.import` 在） | 踩过的坑：拷进来的 PNG 没 `.import` → `ResourceLoader.exists()` 为假 |
| 解析出的路径与 `(关卡索引, weather_type)` **期望表**一致 | 荒漠配到雪地 → 直接失败 |
| 运行时读回 `material_override`：`albedo_texture != null` 且 `albedo_color == WHITE` | 同时挡住"贴图被染成暗绿"那个历史 bug |
| 五关 `.tres` 的 `ground_texture` **显式写死**（不再依赖推断） | 推断只作兜底，且命中兜底要打印警告 |

## 八、风险与回退

| 风险 | 应对 |
|---|---|
| 坡 + 发夹 + 窄路叠加 → AI 上不去 / 车被坡顶弹飞 | 先只在 L1 开 4 m 坡打通链路；每加一关立刻跑 `elevation`+`lap`+`opponents` |
| 三次插值过冲把坡度顶到上限外 | 设计坡度只用上限的 85%；检查采**实测峰值**，超限即红并指出弧长 |
| 地形带替代平板后出界车落到地形上 | 地形带**无碰撞**；护栏 12 m 空气墙拦着；兜底平板降到 `min_road_y−1.5` |
| 地形带与路面接缝出现缝/闪面 | 接缝**共用同一个顶点**；`--check=elevation` 的地形不变量 + 一条"路沿外侧 0.1 m 处射线必须命中地形" |
| L3 下凹弯把路面埋进兜底平板 | `plate_top` 按 `min_road_y` 算，不写死 0；断言 `plate_top ≤ min_road_y − 1.0` |
| AI 改动把 L5 上原本正常的行驶弄坏 | `opponents` 双关卡（4 与 5）都要求零自救；每步都跑 |
| 起伏让 `--check=wallslide` 的视觉穿模判据失效 | 该判据按 `rail_half`（跟着曲线走）比较，天然适配坡道 |
| 改动引入"改了但没证据"的行为变化 | 每步必须有断言或数字；没有就回退（已执行过一次） |

**回退方式**：每一步一个提交；任何一步转不了绿就 `git revert` 该提交，
并在 `docs/testing.md` 的"已知缺陷"里如实记一条（含实测数据）。
