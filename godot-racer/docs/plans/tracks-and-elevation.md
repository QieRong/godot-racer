## 一、P2 · 赛道重设计（形状 + 起伏）

### 1.1 现状问题（你指出的）

`track_generator.gd` 目前**只有一种赛道形态**：椭圆 + 正弦半径扰动
（`radius_x` / `radius_z` / `s_curve_amplitude` / `s_curve_waves`）。
所以 5 个关卡本质是**同一个公式换参数**，不是各自设计的赛道。而且**全是平的**。

### 1.2 架构改动：形态与起伏解耦

引入两层，互不干扰：

| 层 | 做法 | 为什么分开 |
|---|---|---|
| **形态（XZ 平面）** | 从"椭圆公式"改为**路段拼装**：一关由若干路段串成 | 才能做出直道/发夹/连续直角弯等真正的布局差异 |
| **起伏（Y 高度）** | 沿弧长的一条**独立高度剖面**（控制点 + 平滑插值） | 形状和坡度可以各自调；不会"调形状把坡度弄坏" |

关键实现点：**最终仍然烘焙成一条 `Curve3D`**。
现有所有采样/查询接口（`centerline_point` / `nearest_on_centerline` / `road_length` …）
全部不用改，改动被限制在生成器内部。

### 1.3 路段词汇

| 路段 | 参数 | 用途 |
|---|---|---|
| `straight` | 长度 | 直道 |
| `arc` | 半径、角度 | 定半径弯 |
| `hairpin` | 半径 | 发夹弯（约 180° 掉头） |
| `chicane` | 长度、偏移 | S 型连续变向 |
| `sweeper` | 半径、角度 | 大半径高速弯 |

数据写法（两种，请你选一种）：

- **(A) 资源数组**（更 Godot 惯用、有类型检查）：
  `@export var segments: Array[TrackSegment]`，每段是 `.tres` 子资源，字段
  `kind / length / radius / angle_deg`。缺点：`.tres` 手写较啰嗦。
- **(B) 文本 DSL**（改起来最快、diff 最易读）：
  `@export var layout := "straight:120, sweeper:150:90, hairpin:25"`
  生成器解析成路段。缺点：没有类型检查，拼错要运行时才发现（可加解析校验）。

> 我倾向 **(B) + 解析期校验**：5 条赛道要反复手调，DSL 的迭代速度优势很大；
> 配一个 `--check=layout` 把拼写错误在验收里挡住。

### 1.4 闭环问题（这是个真风险）

椭圆天然闭环，**手工拼路段不保证首尾相接**。方案：

1. 生成器拼出骨架折线后，**计算闭环误差**并打印；
2. 误差 ≤ 0.5 m：把残差**按比例摊到各直道**上微调（不改变形态特征）；
3. 误差 > 0.5 m：直接**报错并要求改设计**（不静默修正，否则形状被悄悄改掉）；
4. `--check=layout` 把"闭环误差 ≤ 0.1 m"列为硬指标。

### 1.5 转弯半径的硬约束（必须先算）

车的最小转弯半径 ≈ 轴距 / tan(最大转角) = 2.1 / tan(0.5 rad) ≈ **3.8 m**（静止理想值）。
实际高速下远大于此。所以：

- **窄路关卡最小弯半径 ≥ 20 m**（否则低速也转不过来，只能靠撞墙）
- **高速路段弯半径 ≥ 40 m**
- `--check=layout` 校验"最小弯半径"，并把每关的弯道按半径分档统计出来，便于核对设计意图

### 1.6 五关的具体设计（请重点审这一节）

| 关 | 形态（路段序列） | 起伏 | 设计意图 |
|---|---|---|---|
| **1 新兵训练营** | 宽路椭圆 + 一条短直道（≈ 现状，但路更宽） | **无** | 学会开：不打滑、不撞墙 |
| **2 阳光竞速场** | 长直道 → 两个大半径扫弯 → **一个低速发夹** | 1~2 处缓坡（≤5 m） | 学会刹车点与走线 |
| **3 雨夜街道** | **窄路 + 连续直角弯**（街道网格感） | **一处下凹积水弯** | 低抓地力下控车 |
| **4 荒漠遗迹** | 长波浪直道 + 沙丘 + 障碍 | **起伏最明显**（≤8 m、多波） | 高速 + 起伏 + 避障 |
| **5 极地挑战** | **连续发夹 + 冰面** | 明显上下坡（雪坡） | 综合考验 |

**起伏强度（按你选的"温和：真实公路感"）**：
高度 4~8 m、每圈 2~3 个坡、坡度 ≤9%（硬上限 12%，超限自动夹紧并告警）。

### 1.7 有坡之后**必须一起改**的地方（漏一个就出怪问题）

| 位置 | 现状 | 为什么必须改 |
|---|---|---|
| 地面 | **一整块平板** | 有坡后路面会埋进去/悬空 → 改成**跟随赛道的宽地形带**（两侧各约 120 m）+ 底下留兜底平板 |
| 出生点 | 高度写死 | 要取起跑线的路面 Y |
| 复位 / 出界拉回 | 落点 Y 写死 | 否则瞬移到地下或空中 |
| 障碍（静态+动态） | **Y 写死成障碍高度** | 会浮空/埋地 → 取该弧长的路面 Y |
| `--check=enclosure` | 射线起点高度 | 要跟曲线，否则坡上误报缺口 |
| AI | 转向已忽略 Y（对） | 但**上坡要收油、下坡可晚刹**，否则上不去坡 |
| 相机 | — | 确认跟随用车的绝对 Y（预计不用改，要验） |
| 小地图 | 俯视 | 不受影响；可选加坡道明暗 |

**刻意不做**：路面**不加倾斜（banking）**。倾斜会和防翻车逻辑打架，
而且玩家难以判断车身姿态。这是取舍，不是遗漏。

### 1.8 实施顺序（**一关一关来，不一次全改**）

1. **等價复刻**：先用新路段系统 **复刻出现在的椭圆赛道**，让**所有现有验收保持不变**。
   —— 这一步证明"新系统无损"，是后面敢改的前提。
2. **起伏管道**：高度剖面 + 地形跟随 + 1.7 表里所有 Y 相关修正；
   只在第 1 关开一个 4 m 小坡打通链路。
3. **逐关设计形态**：1 → 5，每关做完立刻跑全套验收。
4. **逐关设计起伏**：同样 1 → 5。
5. 全量回归 + 逐关截图 + 提交推送。

### 1.9 验收标准（P2）

**新增两个检查**：

- `--check=layout`：闭环误差 ≤0.1 m；最小弯半径 ≥ 该关下限；弯道半径分档统计与设计一致；
  DSL 解析无残留 token。
- `--check=elevation`：坡度全程 ≤ 上限；剖面闭环（Y(0) == Y(L)）；
  坡面上**四轮全部接地**（不悬空）；剖面曲率有界（坡顶不把车弹飞）；不与地面穿模；
  **每关都能跑完一圈 + AI 也能跑完一圈**。

**回归（每关都要跑）**：`enclosure` / `wallslide` / `lap` / `stress` /
`opponents` / `avoid` / `obstacles` / `weather` / `friction` / `phys`
—— 全绿才算一关做完。

### 1.10 风险与回退

| 风险 | 应对 |
|---|---|
| 坡 + S 弯 + 窄路叠加 → AI 上不去 / 车被坡顶弹飞 | 先 1 关小坡，逐步加；每步跑 `--check=elevation` + `lap` + `opponents` |
| 手工路段拼不闭环 | 见 1.4：报错而不是静默修正 |
| 地形带替代平板后，出界车落到地形上 | 保留兜底平板；`--check=oob` 回归 |
| 起伏让 `enclosure` 误报缺口 | 射线起点跟曲线（1.7） |

## 二、P3 · 翻车后"腹部贴地滑行"（小 bug）

**现象（日志实证）**：玩家车翻车被扶正后，进入 `接地=0/4`、车身高度 y≈0.55、
以 27 km/h **横向滑行 10 秒以上**，脱困逻辑没有救回。

**根因判断**：现有"卡住"判定要求**速度低**（<0.4 m/s 持续 3 秒）。
而腹部贴地滑行的车**速度并不低**，所以判定永远不触发 —— 它能跑，但不可控。

**修复方向**：把"四轮全不接地"也纳入异常判定：
`接地=0/4` 持续 >1.5 s 且车身姿态接近水平（不是腾空飞跃）→ 扶正 + 微抬 + 清零角速度。

**新增** `--check=flip`：强制翻车 → 要求 ≤2 秒内恢复且 `接地=4/4`。
