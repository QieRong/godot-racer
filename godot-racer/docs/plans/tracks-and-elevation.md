## 一、P3（**先做**，约 20 分钟）：翻车后"腹部贴地滑行"

### 1.1 现象（日志实证）

玩家车翻车被扶正后，进入 `接地=0/4`、车身 `y≈0.55`、以 **27 km/h 横向滑行 10 秒以上**，
脱困逻辑没有救回。

### 1.2 根因（代码实证，不是猜）

`vehicle.gd:_check_recovery()`（第 653 行）只有两个出口：

| 判据 | 代码 | 为什么漏掉这个 case |
|---|---|---|
| 翻车 | `up.dot(UP) < cos(70°)`（第 659 行） | 腹部贴地时车身**基本水平**，`up·UP ≈ 1`，判不出"翻车" |
| 卡住 | `planar < stuck_speed(1.0 m/s)` 持续 `recover_delay(4 s)`（第 663、685 行） | 腹部滑行的车**有 27 km/h**，速度并不低 → 永不触发 |

结论：**"四轮全不接地"这个状态根本没有任何判定在管它。**

### 1.3 修复规范

在 `vehicle.gd` 新增：

```gdscript
## 腹部贴地滑行：四轮全不接地、但车身基本水平、且贴着路面在滑。
@export var belly_slide_grace := 1.5      # 秒，持续多久才判定
@export var belly_upright_angle := 25.0   # 度，姿态在这个范围内算"正常朝上"（不是腾空翻车）
@export var belly_lift := 0.45            # 米，扶起时抬离地面
@export var belly_impulse_dv := 0.5       # m/s，向上补的速度增量（注意是速度，不是冲量！）
var _belly_time := 0.0
```

判定（插在 `_check_recovery()` 的翻车判定之后、卡住判定之前）：

```gdscript
var gcount := grounded_wheel_count()          # 新增：遍历子节点里 VehicleWheel3D 数 is_in_contact()
var upright := up.dot(Vector3.UP) > cos(deg_to_rad(belly_upright_angle))
var near_surface := true
if _track != null:
    var near := _nearest_track_point()
    if not near.is_empty():
        # 贴地滑行 = 车底离路面 < 1.0m；真正腾空飞跃会高得多，两者必须区分开
        near_surface = (global_position.y - float(near["pos"].y)) < 1.0
if gcount == 0 and upright and near_surface and planar > 2.0:
    _belly_time += delta
else:
    _belly_time = 0.0
if _belly_time >= belly_slide_grace:
    print("[车辆] 腹部贴地滑行 %.1fs（接地 0/4 姿态水平 y=%.2f 速度 %.1f km/h）→ 扶起"
        % [_belly_time, global_position.y, planar * 3.6])
    recover_from_belly_slide()
    _belly_time = 0.0
```

新函数（**注意你批注里写的 `apply_central_impulse(Vector3.UP * 0.5)` 我改了写法，理由在下面**）：

```gdscript
## 从"腹部贴地"状态扶起来。
##
## ⚠ 为什么冲量必须乘 mass：apply_central_impulse 的单位是 N·s（kg·m/s）。
## 本车质量约 1000kg，直接给 0.5 N·s 只产生 0.5mm/s 的速度增量 —— 等于没给，
## 下一个物理帧还会立刻重新贴回地面（这正是你担心的"扶不起来"）。
## 写成 (Vector3.UP * belly_impulse_dv * mass) 后，Δv 才是可控的 0.5 m/s。
func recover_from_belly_slide() -> void:
    global_transform.basis = Basis.looking_at(_flat_forward(), Vector3.UP)
    global_position += Vector3.UP * belly_lift
    linear_velocity = Vector3.ZERO
    angular_velocity = Vector3.ZERO      # 不清角速度的话，下一帧姿态又会歪
    apply_central_impulse(Vector3.UP * belly_impulse_dv * mass)
```

> 补充说明：`recover_upright()`（已有函数）**本来就已经**清零了 `linear_velocity` 与
> `angular_velocity`（第 1030-1031 行），所以你批注的那半条已经满足；缺的是
> **判定**（§1.2 的两个出口都不认这个状态）和**向上补速度**。

## 三、P2 架构：形态 / 起伏 / 地形 三层解耦

| 层 | 做什么 | 产出 |

| **形态（XZ）** | 路段 DSL 拼装骨架 → 闭环解算 → 密集折线 | 一条闭合的中心线（y=0） |

### 3.1 路段 DSL 文法（拍板：B 方案）

```
layout     := seg ("," seg)*
seg        := kind ":" num (":" num)*
kind       := "straight" | "arc" | "sweeper" | "hairpin" | "chicane" | "ellipse"(仅阶段 1)
straight:L              直道，L>0 米
arc:R:A                 定半径弯，R>0 米；A 有符号角度，正=左转，负=右转，|A|≤270
sweeper:R:A             同 arc；R≥40m 时统计上归入"高速弯"（不强制）
hairpin:R               等价 arc:R:180（左转发夹）
chicane:R:OFF           S 弯：两段 ±a 的等半径弧，a = acos(1 - OFF/(2R))，需 OFF<4R
                        路径长 = 2·R·a（由 R、OFF 决定，不再单独给长度）
ellipse:RX:RZ[:WAVES:AMP]   ⚠ 仅用于阶段 1 的"逐点对照"，阶段 3 结束时必须删除
```

**严格解析校验**（`--check=layout` 的硬指标，逐条报错并给出位置）：

1. 每个逗号分段必须完整匹配 `^\s*kind\s*:\s*num(\s*:\s*num)*\s*$` —— 任何**残留 token**（拼错 kind、多个冒号、尾随逗号、中文标点）都报错；
2. 参数个数必须与 kind 匹配（多一个少一个都报错，并打印该 kind 的合法形式）；
3. 数值必须是有限数：`is_finite()`、拒绝 NaN/INF/科学计数法/负半径；
4. `R>0`、`L>0`、`|A|≤270`、`OFF<4R`；
5. 未知 kind → 报错并列出**全部**合法 kind（这条同时是"`ellipse` 真的删掉了"的证明）。

> 为什么不做 (A) 资源数组：5 条赛道要反复手调，DSL 的迭代速度和 diff 可读性优势很大；
> 类型安全的缺口由上面的解析校验补上，而且**每次启动关卡都会跑**，比编辑器报错更早暴露。

### 3.2 闭环：三种模式，绝不静默修正

| 模式 | 用于 | 做法 |
|---|---|---|
`mirror180` | L1、L5 | 只写"半条"，净转角**恰好 180°**；另一半用**点对称**（绕半程终点转 180° 再平移）生成 → **数学上精确闭环**，且接缝处航向连续 |
`solve` | L2、L3、L4 | 全条写出；解 2×2 线性方程组，把残差摊到**两条可调直道**上 |
`exact` | 阶段 1 的 `ellipse` | 天然闭环 |

`solve` 的硬约束（都要报错，不静默）：

- 净转角必须 ≈ 360°（容差 0.5°）。不够就报"净转角 275°，还差 85°"；
- 两条可调直道必须**不平行**（行列式 `|det| > sin(11°) ≈ 0.19`）。若几乎平行 →
  报"两条可调直道夹角仅 3°，无法闭环：请把其中一条改成不同朝向的直道"；
  （**这条很重要**：平行直道只有 1 个自由度，方程组无解，硬解会得到荒谬的长度）
- 解出来的直道长度必须仍 > 5 m，否则报错；
- 闭环残差 ≤ **0.1 m** 才算过。

### 3.3 曲率连续性 —— 这是本项目**真实炸过车**的地方

`track_generator.gd` 第 136-139 行留着实测教训：早期"直线+圆角矩形"版本
**在直道/圆弧接点曲率突变，车被弹飞**（y 从 −0.06 瞬间跳到 +0.79，整车腾空后失控）。
所以路段拼装**必须**配一套曲率体检，不能只看形状好不好看：

- 骨架按**固定 2 m 站距**采样（`sample_step`），不按"每段一个点"（那样是硬折角，就是当年的炸车原因）；
- 最终 `Curve3D` 用 `cubic_interp = true` + `bake_interval = 0.5`，密集点上的 Catmull-Rom
  会把接点轻微抹圆（这正是我们要的）；
- `--check=layout` 逐站统计并断言：
  - 每 2 m 的**航向变化** ≤ 8°（`arc:18` 的极限值 = 6.4°，留 25% 余量）；
  - 每 2 m 的**曲率跳变** `|Δκ|` ≤ 0.030 (1/m)；
  - 阈值不是拍脑袋：先测 `ellipse:320:200`（现役赛道）的基线，再取 `max(基线×1.5, 理论值)`；
- **内护栏自交检查**：内偏 `rail_half_width()` 后的折线做段-段相交检测，
  并断言 `R_min − rail_half > 2.0 m`。发夹弯若自交，`enclosure` 射线会打到"另一侧的墙"
  而**假通过** —— 那种错必须靠几何检查挡，不能靠射线。

### 3.4 `nearest_on_centerline` 的发夹弯歧义（新赛道形状带来的必改项）

它现在按 **XZ 平面距离**找最近点（第 612 行）。发夹弯两侧的 XZ 距离可能只有 ~36 m 而弧长差 56 m，
所以在**提示弧长失效**（复位/瞬移后走全周粗扫）时，可能把车认到**对面那条腿**上 → 复位后车头朝反方向。

修法：保留原逻辑，只加一条**平局裁决** —— 若两个候选的 XZ 距离都 < 3 m 且相差 < 0.5 m，
取**弧长离 `hint_arc` 更近**的那个。`--check=layout` 加一项**往返唯一性**测试：

> 对每 2 m 一个站（共 ~400 个）：`nearest_on_centerline(centerline_point(s), hint=s)`
> 返回的 `arc` 与 `s` 差 ≤ 2 m，且 `forward · centerline_forward(s) > 0.9`。

## 四、AI：上坡收油 / 下坡早刹 / 物理极限

### 4.1 坡度感知（对应你的批注 3）

前视 8 m 取高度差算坡度（`grade = (y(arc+8) − y(arc)) / 8`）：

```gdscript
const SLOPE_PROBE_AHEAD := 8.0
const SLOPE_DEADBAND := 0.03      # 3% 以内当平路，避免噪声抖动
const SLOPE_GAIN := 4.0
const SLOPE_MIN_FRAC := 0.55
```

- `grade > 3%`（上坡）→ `limit *= clampf(1 - SLOPE_GAIN*(grade - 0.03), 0.55, 1.0)`
  （12% 坡 → 收油到 64%）。**物理依据**：12% 坡的沿坡重力分量 = 0.12g ≈ 1.18 m/s²，
  持续上坡时动力裕度被吃掉，不收油会掉速甚至上不去；
- `grade < −3%`（下坡）→ **延长刹车预判**：把弯道采样的 12/28/48/72 m 乘
  `(1 + 0.6·clampf(−grade/0.12, 0, 1))`，并把"超速才刹车"的死区从 3.0 m/s 收到 1.5 m/s
  （下坡滑行加速快，等超速 3 m/s 再刹就晚了）。

### 4.2 抽成共享模块（避免两套逻辑漂移）

新增 `scripts/racing_line.gd`（纯函数，约 120 行）：

```gdscript
static func slope_at(track: Node, arc: float, probe := 8.0) -> float
static func corner_radius_at(track: Node, arc: float, ds := 12.0) -> float   # 由折角反推 R
static func speed_limit_kmh(radius: float, a_lat: float, safety := 0.85) -> float
```

**三处共用同一个数据源**：`ai_opponent.gd`、`main.gd` 的验收自动驾驶（`--check=lap`/`elevation`
都靠它开）、以及验收打印。这直接对应本项目最惨的一次教训（游玩与验收走了两条不同代码路径 →
验收报 ✔ 而游戏是错的）。

### 4.3 ⚠ 物理极限限速（v1 漏了，不修 L5 必炸）

现状：AI 弯道限速靠"折角 → 百分比"，下限 `min_speed_frac = 0.30`。
L5 极地：极速 240×0.9 = 216 km/h，所以**最低只能降到 65 km/h**。
但冰面 `a_lat = 16.0 × 0.5 = 8.0 m/s²`、发夹弯 `R=18 m`：

```
v_max = sqrt(a_lat · R) = sqrt(8.0 × 18) = 12.0 m/s = 43.2 km/h   （×0.85 安全系数 → 36.7）
```

**65 > 43.2** → AI 在冰面发夹弯必然推头出界。修法：

- `setup()` 里注入抓地力时同时把 `max_lateral_accel` 按 `friction_multiplier` 缩放
  （并保存基准值，避免反复 setup 越乘越小）；
- `_target_speed()` 里增加一条**不受百分比下限约束**的物理限速：
  `limit = min(limit, speed_limit_kmh(R_i, a_lat))`；
- 即：`min_speed_frac` 是"对极速的下限"，物理极限是"对地面的上限"，**两者取小**，
  物理极限**不允许**被百分比下限抬回去。

各关实测对照（用现役 `max_lateral_accel = 16.0`）：

| 关 | μ 倍率 | a_lat | 最紧弯 R | 物理限速 | 现下限(30%) | 是否够 |
|---|---|---|---|---|---|---|
| L3 雨夜 | 0.7 | 11.2 | 20 | 54 km/h | 54 km/h | 刚好 |
| L4 荒漠 | 0.85 | 13.6 | 60 | 103 km/h | 59 km/h | ✔ |
| **L5 极地** | 0.5 | 8.0 | 18 | **37 km/h** | 65 km/h | ❌ 必须修 |

## 五、起伏与地形（你的批注 1、2）

### 5.1 生成顺序（顺序错了长度就错）

1. DSL → XZ 骨架 → 闭环解算 → 密集折线（2 m 站距，y=0）；
2. `Curve3D(cubic_interp=true, bake_interval=0.5)`，`L_xz = get_baked_length()`；
3. 高度剖面按 `L_xz` 采样，把 Y **写进每个站点的控制点**；
4. 重建最终 `Curve3D`，`_road_length = get_baked_length()`（此时是**三维弧长**）。

> 注意：`bake_interval` **必须显式设置**（默认 0.5 m）。起伏后三维弧长会比 XZ 长
> ≤0.3%（10 m 高差 / 1000 m），所有弧长口径自动一致，无需特殊处理。

### 5.2 高度剖面：`cubic_interp` + 环状鬼点（对应批注 2）

数据：`elevation_profile := "0:0, 0.22:4.5, 0.45:0.8, 0.70:5.0, 1.0:0"`（`t:高度(米)`）。

**C¹ 断点问题**：若直接把 `(0,0)…(L,0)` 喂给 `Curve3D`，接缝两端是**端点**，
Catmull-Rom 的端点切线是单侧估计 → `Y'(0) ≠ Y'(L)` → 每圈在起跑线上被"顶"一下。

**修法（环状鬼点）**：造高度曲线时在两端各补一个**环绕邻点**，让接缝变成内部点：

```
点序列 = [ (t_{n-1}-1, y_{n-1}), (0,y_0), (t_1,y_1), …, (t_{n-1},y_{n-1}), (1+t_1, y_1) ]
```

这样 `Y'(0)` 与 `Y'(L)` 由**同一对邻居**算出 → 数学上相等，接缝天然 C¹。
保留 `height_curve.cubic_interp = true`、`bake_interval = 0.5`，
并要求数据里首尾高度**相同**（都是 0）。

另外：`elevation_profile` 取空串 = 无起伏（L1）；有起伏时控制点之间的**设计坡度
≤ 上限的 85%**，因为三次样条在控制点附近会**过冲** —— 预留余量后实测最大坡度才压得住上限。

### 5.3 地形带：**ArrayMesh，纯视觉**（对应批注 1）

**决定：用 `SurfaceTool` 造 `ArrayMesh`，不用 `GridMesh`。** 理由：

| 方案 | 站距/顶点 | 与路面的接缝 | 结论 |
|---|---|---|---|
| `GridMesh`（规则 XZ 网格） | 1400×240 m、2 m → **约 17 万三角面**，且网格方向与赛道无关 | 接缝必然错开，还得额外补 | ❌ |
| **ArrayMesh（沿赛道横断面）** | 站距 2 m × 每站 10 顶点 → **约 7200 三角面** | 与路面**共用同一个顶点**，数学上无缝 | ✔ |

横断面（每站一次，`H = road_width/2`，`y_i` = 该站路面高度）：

| 横向偏移 w | 高度 | 说明 |
|---|---|---|
| `±H`（路面外沿） | `y_i` | **与路面网格完全同一个顶点** → 无缝、无缝、无缝 |
| `±(H+2.0)` | `y_i − 0.10` | **路肩**：微降排水。护栏在 `H+1.2`，**站在路肩上**（`1.2 < 2.0`，所以护栏底下不会是悬崖） |
| `±(H+8.0)` | `y_i − 0.80` | 路缘带 |
| `±(H+30.0)` | `lerp(y_i − 2.5, plate_top, 0.45)` | 缓坡带 |
| `±(H+120.0)` | `plate_top` | 与兜底平板**齐平** → 边缘不悬空、不穿模 |

`plate_top = min_road_y − 1.5`（曲线建好后算）。**地形不变量**（`--check=elevation` 逐点断言）：

- `terrain_y(w) ≤ y_i − 0.05`（地形永不高过路沿 → 不会盖住路面、不会穿模）；
- `terrain_y(w) ≥ plate_top`（永不掉到平板以下）；
- 外沿 `= plate_top`（不悬空）。

**碰撞：地形带不加碰撞**。因为护栏在 `H+1.2` 处有 12 m 高的空气墙，车**物理上到不了**
地形带上；所以它纯视觉 → 零物理开销、零 trimesh 性能风险（`track_generator.gd` 第 238 行
记录了高面数 trimesh 会让 `VehicleBody3D` 掉帧）。兜底平板继续留在 layer 1 当安全网。

**共用坐标**：把护栏里那段"自适应真实弧长走环"的代码抽成 `_walk_ring(want_step)`，
护栏与地形带**同源**，环首尾重合检查（第 337 行）继续生效。

### 5.4 每关素材绑定（对应批注 7）

现状靠推断：`ground_texture` 留空 → `ground_L<索引>_<天气slug>.png`。
风险就是你担心的：**改了天气或调了关卡顺序，就静默配上另一关的贴图**。

修法两条：

1. **每关 `.tres` 里 `ground_texture` 显式写死**（不再依赖推断）；推断逻辑只作兜底，且命中兜底时**打印警告**；
2. 新增 `--check=assets`，逐关断言：
   - 贴图文件存在**且已导入**（`.import` 在；这是踩过的坑：拷进来的 PNG 没 `.import` → `ResourceLoader.exists()` 为假）；
   - 解析出的路径与 `(关卡索引, weather_type)` **期望表**一致（荒漠配到雪地 → 直接失败）；
   - 运行时读回 `GroundMesh`/地形带的 `material_override`：`albedo_texture != null` 且
     `albedo_color == WHITE`（这条同时挡住"贴图被染成暗绿"那个历史 bug）。

### L1 新兵训练营 —— 宽路圆角矩形（**不是椭圆**）

- `closure_mode = "mirror180"`，半条：`straight:110, arc:70:90, straight:60, arc:70:90`
  （净转角 180° → 点对称加倍成 110/60/110/60 四条直道 + 4 个 R=70 的 90° 弯）
- 长度 ≈ 340 + 2π·70 = **779.8 m**；最小弯半径 70 m；**无起伏**（`elevation_profile = ""`）
- 设计意图：学会开。4 个同半径弯 = 几何完全相同，玩家可以把注意力全放在"不打滑、不撞墙"上；
  两长两短的直道让"加速/刹车"有明确节奏，而不是椭圆那种"永远在轻微转向"。
- 与椭圆的关键差别：**有真正的直道**（可以试到极速）、**弯的曲率是常量**（不像椭圆每点都在变）。

### L2 阳光竞速场 —— 长直道 + 双扫弯 + 一个发夹

- `closure_mode = "solve"`：
  `straight:220, sweeper:95:100, straight:60, sweeper:70:80, straight:35, hairpin:24, straight:90`
- 净转角 100+80+180 = 360° ✔；可调直道 #2（方向 100°）与 #3（方向 180°）夹角 80°（满秩 ✔）
- 长度 ≈ 405 + 165.8 + 97.7 + 75.4 = **743.9 m**；弯道分档：95 / 70 / 24 m
- 起伏（温和，≤5 m）：`0:0, 0.22:4.5, 0.45:0.8, 0.70:5.0, 1.0:0`
  控制点最大坡度 4.5/(0.22·744) = **2.7%**
- 设计意图：学会**刹车点与走线** —— 220 m 直道尾端是 95 m 大扫弯（可全油门过），
  之后 80° 中速弯，最后 24 m 发夹必须刹到低速。

### L3 雨夜街道 —— 窄路 + 连续直角弯（街道网格感）

- `closure_mode = "solve"`：
  `straight:150, arc:20:90, straight:40, chicane:30:4, arc:20:90, straight:160, arc:20:90, straight:60, arc:20:90`
- 净转角 4×90 = 360° ✔（chicane 净 0）；可调直道 #1（0°）与 #2（90°）夹角 90° ✔
- `chicane:30:4` → a = acos(1−4/60) = 21.03°，长 = 2·30·0.3671 = **22.0 m**
- 长度 ≈ 410 + 22.0 + 4·20·π/2 = **557.7 m**；最小弯半径 **20 m**（≥ 20 m 红线）
  内护栏半径 = 20 − (6+1.2) = 12.8 m > 2 m ✔
- 起伏（一处**下凹积水弯**）：`0:0, 0.30:1.2, 0.55:-2.0, 0.75:0.6, 1.0:0`
  控制点最大坡度 3.2/(0.25·558) = **2.3%**
- 设计意图：**窄路 + 直角弯 + 低抓地力**。直角弯逼你"刹-转-出"分段做动作；
  chicane 逼你连续反向修正；下凹弯是唯一会积水的地方（视觉与手感上都"更滑"）。

### L4 荒漠遗迹 —— 长波浪直道 + 沙丘（起伏最大）

- `closure_mode = "solve"`：
  `straight:260, sweeper:110:120, straight:120, arc:80:80, straight:70, arc:70:120, straight:60, arc:60:40`
- 净转角 120+80+120+40 = 360° ✔；可调直道 #2（120°）与 #3（200°）夹角 80° ✔
- 长度 ≈ 510 + 230.4 + 111.7 + 146.6 + 41.9 = **1040.6 m**（最长）；最小弯半径 60 m
- 起伏（**按你拍板夸张到 10 m，坡度上限 12%**）：`grade_limit = 0.12`
  `0:0, 0.05:0.5, 0.155:9.0, 0.26:0.8, 0.40:0.2, 0.50:10.0, 0.61:1.0, 0.75:0.3, 0.85:8.0, 0.95:0.4, 1.0:0`
  控制点最大坡度：第一座沙丘 8.5/(0.105·1041) = **7.8%**；第二座 9.8/(0.10·1041) = **9.4%**
  → 三次样条过冲后实测峰值预计 10~11.5%，**压在 12% 上限内**（超了 `--check=elevation` 会拦住我）
- 设计意图：**高速 + 起伏 + 避障** 三件事同时来。260 m 长直道尽头是 110 m 大弯（要收油但不用刹死），
  沙丘盲顶后面接障碍 —— 这是全游戏唯一"看不见前方"的赛道。

### L5 极地挑战 —— 双发夹 + 连续 S 弯 + 冰面

- `closure_mode = "mirror180"`，半条：`straight:90, chicane:30:4, straight:50, hairpin:18`
  （净转角 = chicane 的 0° + hairpin 的 180° = **180°** ✔ → 点对称加倍成整圈）
- 完整：`straight:90, chicane:30:4, straight:50, hairpin:18, straight:90, chicane:30:4, straight:50, hairpin:18`
- 长度 ≈ 2×(90+22.0+50+56.55) = **437.2 m**；发夹半径 **18 m**（你要求 ≥15 m ✔）
  内护栏半径 = 18 − (4+1.2) = 12.8 m > 2 m ✔
- 起伏（雪坡，上限 8%）：`0:0, 0.20:4.0, 0.45:0.5, 0.70:5.5, 1.0:0`
  控制点最大坡度 4.0/(0.20·437) = **4.6%**
- **关键风险**：冰面物理限速 37 km/h（§4.3）。这一关能不能玩，取决于 §4.3 是否落地。

### 8.2 四轮接地的射线规范（对应你的批注 4）

每个物理帧、四个轮子各一条：

```gdscript
var space := get_world_3d().direct_space_state
var q := PhysicsRayQueryParameters3D.create(
        w.global_position,                                   # 轮心（世界坐标）
        w.global_position + Vector3.DOWN * (w.wheel_radius + 0.60),
        1,                                                   # mask：只打路面/地形（layer 1）
        [car.get_rid()])                                     # 排除自己
var hit := space.intersect_ray(q)
```

- 打空 = 该轮**悬空**；记录 `(弧长, 轮名, 车身 y, 路面 y, 速度)`；
- 判据：**连续打空 > 0.15 s（120Hz 下 18 帧）即失败并退出本项检查** —— 允许的是过坡顶那一瞬的
  正常离地，不允许"某个轮子长期不接地"（那说明地形带/路面对不齐，或有台阶）；
- 顺带统计全程接地率，要求 ≥99%；
- 失败时打印**最严重的 5 处**及其附近的高度剖面，直接定位到是哪个坡做坏了。

## 十、风险与回退

| 风险 | 应对 |
|---|---|
| 坡 + 发夹 + 窄路叠加 → AI 上不去 / 车被坡顶弹飞 | 先 L1 小坡；每加一关立刻跑 `elevation`+`lap`+`opponents` |
| 三次样条过冲把坡度顶到上限外 | 设计坡度只用上限的 85%；`--check=elevation` 采实测峰值，超限即红 |
| 手工路段拼不闭环 / 解算出荒谬长度 | §3.2：报错而不静默修正；平行直道直接拒绝 |
| 发夹弯内护栏自交 | §3.3 几何自交检测（射线会假通过，不能只靠射线） |
| 地形带替代平板后出界车落到地形上 | 地形带无碰撞；护栏 12 m 空气墙拦着；兜底平板降到 `min_road_y−1.5` |
| L5 冰面发夹弯 AI 出界 | §4.3 物理极限限速（**不落地就不做 L5**） |
| 某关调完形态把坡度弄坏 | 形态与高度是两套独立数据，互不干扰（§三） |
| 新检查太多拖慢验收 | 单关回归仍 <2 分钟；`layout`/`assets` 是静态检查（毫秒级） |
