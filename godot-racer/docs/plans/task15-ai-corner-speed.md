# 任务 15 设计 v2：AI 弯道限速（根因已实测确认为几何 bug）

> 状态：**v2，待最终确认**。v1 的 §2.1 口径有致命遗漏（见 §二），已修正。
> 对应计划 `docs/plans/phase2-elevation-pipeline.md` §六 任务表第 15 项。
> 触发原因：项目所有者试玩反馈「AI 车手速度太慢，应该和最高限速差不多」。

**v1 → v2 改了什么**：v1 只打算"接物理极限"，并假设这样 L1 会变快。
项目所有者当场指出 `min(43.2, 146) = 43.2`，对 L1 **毫无帮助**。
顺着这个质疑实测，发现 `_target_speed()` 的弯度测量有一个**退化向量 bug**，
它才是把 L1/L5 都钉在 30% 下限的直接原因。**v2 必须同时修它**，否则
「AI 慢」这个需求只被部分解决。

## 〇、v3 实测订正（2026-09，红用例跑出来之后写的）

> 这一节是**实测**推翻了 v2 里两处书面判断。按项目所有者要求：直接改成实测口径，
> 并明确标注"原判断有误"——不留两处互相矛盾的结论。

**订正 1（原判断有误）：「改前最终目标被钉在 43.2 → 80 km/h 阈值今天必红」——不成立。**
实测改前 L1 逐帧**最大值就是 117.7~118.0 km/h**（两次独立运行）。
原因：噪声折角随位置在 101.5°~121.1° 之间漂，**少数帧它自己就小了**，
那些帧的策略限速能到 105~118。所以：

- 用 **80** 当"最大值哨兵"阈值 → 改前实测**绿**，是一条**假判据**；
- 改用 **110**（约极速 144 的 76%）→ 改前 117.7~118.0 会挂、改后稳过；
- 但**靠最大值本身就是脆的**（坏状态靠少数幸运帧就能过）。真正的稳健判据是
  **「被钉住的帧占比」**：改前实测 **72.3%** 的帧 < 80 km/h（必红），改后 0.0%。

**订正 2（原判断有误）：「改后 105~120」不是成绩证 —— 那正好是改前的噪声顶。**
改前最大已经 117.8，所以"117.8"这个数**不能**用来证明改后变快了。
改后的成绩只能看**分布**与直道段的策略值，实测（仅修①、②③ 未接线）：

| 指标（L1，`--check=aidiag`，逐帧 2375 帧） | 改前 | 仅修① |
|---|---|---|
| 策略限速（逐 2.5s 采样） | 43.2（饱和） | **94~130** |
| 最终目标最大值 | 117.7~118.0 | 129.8 |
| **< 80 km/h 的帧占比** | **72.3%** | **0.0%** |
| **≥ 本关极速 × 85% 的帧占比** | **0%** | **63.8%** |
| 裸弯读数（`@d=12`） | 101.5°~121.1°（噪声） | 不再出现（≤3.5°） |

**订正 3（判据设计错误）：「≥ 物理上限 × 0.85 的占比 ≥ 80%」改前改后都是 0%。**
这条 v2 的主判据**区分不了两个状态**：L1 上是**策略**在限速（目标 94~130），
地面能给 138~276 —— "离物理上限还差一半"是**正常且安全**的（物理上限是天花板，
不是目标）。现改为：

- **主判据**：`最终目标 ≥ 本关极速 × 0.85` 的帧占比 ≥ 80%（改前 0% / 改后 63.8%，能区分）；
- **辅助读数**：仍按原口径打印 `≥ 物理上限 × 0.85` 的占比，但它**不计入通过/失败** ——
  它回答的是另一个问题："AI 有没有被**地面**限制住"，在 L5 冰面那种低抓地力关卡才该当主判据。

## 一、根因（全部有实测数据）

### 1.1 直接原因：弯度测量里的**退化向量**

`ai_opponent.gd:465-484`：

```gdscript
var prev: Vector3 = _lane_point(_arc)          # ← prev 是"车所在的车道点"
for d in [12.0, 28.0, 48.0, 72.0]:
    var p: Vector3 = _lane_point(_arc + d)
    var a := prev - global_position             # ← 第一档时 a ≈ 车位置 − 车位置 ≈ 0
    var b := p - prev
    if a.length() > 0.5 and b.length() > 0.5:   # ← 0.5~0.6 刚好被放行
        var bend := absf(a.normalized().angle_to(b.normalized()))
```

实测明细（`--check=aidiag`，L1）：

```
d=12 距车=0.6 |a|=0.6 |b|=12.2 夹角=101.5°     ← |a| 只有 0.6m，夹角是纯噪声
```

`|a| = 0.5~0.6`（AI 一直正好跑在 `lane_offset` 车道点上，所以第一档向量退化）。
**拿一个 0.6m 的向量和 12m 的向量求夹角得到 101°**，而它被当成"最严格的一档"，
于是：

    策略限速 = 144 × clampf(1 − 101°/25°, 0.30, 1.0) = 144 × 0.30 = 43.2 km/h

**与真实弯度无关。** 同一时刻的真实半径是 142~499 米（12m 弦折角 1.4°~4.8°）。
L5 冰面同样（裸弯 97~114°），说明这是**普遍现象，不是某一关的特例**。

### 1.2 次要原因：把"极速"当成"物理极限"

即使修掉 1.1，`speed_cap_kmh × frac` 仍然是个凭经验拍的百分比，
与抓地力、半径无关。实测两头的错误：

| | 物理上限 | 旧策略限速 | |
|---|---|---|---|
| L1 R=168m 干燥 | 159 | 43.2（被 1.1 压死） | 慢到 27% |
| L5 R=6499m 近似直道 | **698** | 64.8 | 慢到 **9%** |
| L5 R=34m 冰面 | **51** | **64.8** | **超速 27%（危险）** |

**同一个公式，在直道上慢到 9%，在冰面上快得危险** —— 因为它压根不看路面。

### 1.3 隐藏必需项：`max_lateral_accel` 未按抓地力缩放

`ai_opponent.gd:41` 固定 `16.0`；玩家车 `vehicle.gd` 会按 `friction_multiplier`
缩放它，而 AI 的 `apply_friction()`（`ai_opponent.gd:243`）**只缩了轮胎摩擦**。
**不修这条，物理极限在 L5 上会算成干燥路的 96 km/h 而不是 51** ——
现象是"AI 在冰面依然推头"，极易被误判成"物理极限这条路走不通"。

## 二、修改口径（v2 修正版）

### 2.0 ⚠ 修正：**必须同时修 1.1 的退化向量**，否则 L1 不变

这就是项目所有者指出的盲点。三条改动缺一不可：

| 改动 | 解决什么 | 不做的后果 |
|---|---|---|
| **① 修 `|a|` 退化向量** | 策略限速不再被噪声压死 | L1 仍 43.2，`min()` 照抄它 → **任务对 L1 无效** |
| **② 接物理上限** | 直道上不再凭空慢、冰面上不超速 | 干燥路仍慢、冰面仍危险 |
| **③ 缩放 `max_lateral_accel`** | ②在低抓地力关卡才算得对 | L5 用干燥路上限 → ②失效 |

### 2.1 修法（①）：让每一档都量"真实转弯"

`bend` 的正确语义是**相邻两段行进方向的夹角**。第一档的参考向量不该是
"车→车道点"那 0.6 米，而应该是**同一采样序列内的前一段**。所以改成"先取点列、
再逐对求夹角"，彻底消掉退化向量：

```gdscript
# 先把前方采样点全部取出来（第一点是车所在弧长处的车道点）
var pts := [_lane_point(_arc)]
for d in [12.0, 28.0, 48.0, 72.0]:
    pts.append(_lane_point(_arc + d))
# 再对"点列内的相邻两段"求夹角（i 从 1 起 → a、b 都是 12~20m 量级，不可能退化）
for i in range(1, pts.size() - 1):
    var a: Vector3 = pts[i] - pts[i - 1]
    var b: Vector3 = pts[i + 1] - pts[i]
    a.y = 0.0
    b.y = 0.0
    if a.length() > MIN_BEND_SEG and b.length() > MIN_BEND_SEG:
        var bend := absf(a.normalized().angle_to(b.normalized()))
```

并把守卫从 `0.5` 提到 **`MIN_BEND_SEG = 3.0`**（米）：0.5m 对 12m 求夹角在数值上
毫无意义（方向这个量还没成立），3m 才保证有意义。**这条守卫自己也要有用例钉住**
（用例 ⑦），防止有人把它调回去。

### 2.2 接物理上限（②）：`目标 = min(策略限速, 物理上限)`

```gdscript
# racing_line.gd 新增（单一来源，AI 与验收共用）
static func ai_target_speed_kmh(percent_kmh: float, radius: float, a_lat: float,
        safety := 0.85) -> float:
    return minf(percent_kmh, speed_limit_kmh(radius, a_lat, safety))
```

`_target_speed()` 的每个采样点再夹一层。**语义（按你确认的 A）**：

> **物理极限是地面的天花板，策略下限是 AI 愿意降到多慢的地板。
> 地板不允许高于天花板。**

`min_speed_frac` **保留**，但它只约束**策略限速**那一项；物理上限不受它约束
（最终仍取 `min`）。注释里写明：**「它不再是绝对下限，物理上限永远优先」**。

### 2.3 缩放 `max_lateral_accel`（③）

`setup()` 里记录基准值、按 `friction_multiplier` 缩放，**每次从基准重算**
（不能连乘 —— 与既有 `apply_friction()` 的 `_wheel_friction_base` 同做法）。

### 2.4 本轮不动（按你确认）

- `_update_drive` 的 0.72 收油 → **15b**
- `_roll_guard_factor` 的方向盘量程 → **15b**
- 刹车距离前瞻 → 任务 7（`brake_distance()` 已备好）
- `ai_speed_scale`、任何关卡 `.tres` → 不动

**退化向量的在场景取证**（`--check=aidiag` 每跑必打一次）：
第一段参考向量 |a|、旧口径夹角、新口径夹角三个数并排 —— 让"退化"一眼可见，
而不是靠从目标速度反推（**反推不可靠**，见 `docs/engineering-notes.md` 第 54 条）。

### 3.1 本轮**未解决**的缺口（必须写清，不许当成功）

L1 上"恰好跑到 144（本关极速）"的帧是 **0%**，最终目标最大 **129.8（= 极速的 90%）**。
原因是策略公式 `frac = 1 − bend/25°` 只在 `bend == 0` 时给满极速，
而 L1 最直的一段**实测仍有 2.5° 折角** → 公式给 `144 × 0.9 = 129.5`。

- 从 **43.2 → 129.8** 是本任务（①②③）的功劳，需求的可度量部分已达成；
- 从 **129.8 → 144** 需要动 `corner_slowdown` 或"弯度 → 限速"的映射形状，
  那会**改变 AI 的驾驶风格**（更快入弯 = 更容易推头），属必须单独裁决的改动，
  **不在本任务里顺手改**。已把这条写进 `main.gd` 的判据注释里，防止有人为了让
  判据好看去偷偷调参。
